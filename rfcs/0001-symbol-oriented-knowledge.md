# RFC 0001 · 以 DARI 公开符号组织知识发现与详情

草案。跟踪 [dari #8](https://github.com/hh9527/dari/issues/8)。

## 作者界面

发现入口 `{ queries: [{ entity, member?, value? }] }` 接收实体词和至少一个成员词或具名值。三个入口沿用模糊匹配。实体圈定候选数据集，成员词匹配维度和度量，具名值通过所属值类型反查对应成员。成员词命中与具名值命中取并集。计数属于度量。

发现回执按数据集列出命中的维度和度量。模型的主时钟有唯一支持半开窗口筛选的直接维度时，数据集标题下同时列出该成员。数据集标题给出完整 path，成员行使用数据集内的短名和类型签名。将标题与成员名用 `::` 连接，即可得到传给 `dari_kg_info` 的完整 ID。成员共用数据集内的名称空间。独立发布的值类型使用完整 ID 引用，重点覆盖 newtype 和 sum type。基础类型和通用模板直接出现在签名中，例如 `Option(T)` 和 `Reference(ic::TenantById)`。成员可空性由签名中的 `Option(T)` 表达。通用模板由语言提供，其用法见语言手册。info 展开模板实参中的业务类型，例如 `ic::TenantById`。模型字段用于内部映射和检索，公开目录由可查询成员构成。

```text
## ic::CurrentAlarm
- dimension alarm_severity: ic::AlarmSeverity
- measure alarm_count: Int
```

`ic::Dataset`、`ic::Type` 和 `ic::Dataset::member` 是完整 ID。本文采用具名 Telora struct 作为数据集公开名称的来源，数据集内部身份及物理表由模型单独维护。多个数据集共用物理表时，各具名声明保留独立的公开符号。查询通过 `from(ic::CurrentAlarm)` 绑定数据集，再用局部绑定引用成员，例如 `a.alarm_severity`。

`dari_kg_info({ids:[...]})` 对公开 ID 精确匹配。每项以 `### <full-path-id>` 为标题，单行签名和查询能力用列表呈现，值类型声明使用 `telora` 代码块。数据集详情说明业务对象、粒度、覆盖范围和时间口径。成员详情给出签名及影响查询选择的业务口径，例如某个计数只统计未清除的记录。值类型详情给出 Telora 声明，同一个类型可以被多个成员引用。

路由的起点、终点和必经数据集沿用发现回执的公开路径。路由回执以公开路径呈现数据集和关系，关系路径可直接用于详情查询。

## 模型枚举声明

模型枚举采用与 Telora 一致的 `enum { ... }` 语法。info 在类型标题中给出完整公开符号，例如 `ic::AlarmSeverity`，再展示成员声明。

```telora
type AlarmSeverity = enum {
    Critical, # 紧急
    Major,    # 重要
    Minor,    # 次要
    Warning,  # 提示
};
```

枚举定义权属于模型。DARI 的模型声明视图识别同样的 enum 形式，普通 DARI 稿件只能引用已经发布的类型及成员。作者可以直接使用成员，也可以为已有类型写本地别名。

```dari
type Severity = ic::AlarmSeverity;
data critical = ic::AlarmSeverity::Critical;
```

枚举声明与用法分别标识。模型声明视图中的 enum 片段按共享声明语法验证，并核对成员与同版模型契约相符。普通稿件中的引用由 DARI checker 校验，本地 enum 定义应报告诊断。声明列出成员的顺序不代表业务排序，排序能力由模型单独发布。

默认隐藏仅供 codec、别名归一和 SQL lowering 使用的 wire 映射。任务涉及原始编码时，按需说明对应关系。独立发布的原始字段仍可发现和查询。多 wire 映射到同一 Variant 时，声明只显示一个 Variant。模型分别说明 Unknown 成员和 SQL NULL。

## 跨仓职责

ontology 从同一次模型准备发布精确符号、类型、枚举成员、查询授权、业务说明和概念关联。知识与检查使用同一权威来源，公开名称由模型显式提供。适配器保留模型版本与符号身份。

DARI 负责打印声明和用法。info、发现详情和 LSP 可选择不同详略程度，共用符号和类型展示规则。语法无法承载的约束用说明或注释表达，作者视图以这些内容替换重复的 JSON 展开。完整执行契约仍由适配器消费。

## 实施与验收

1. 在 ontology 建立关联实施 issue，用真实模型确定封闭枚举、多 wire 分类、带量纲类型、可空成员、数据集和关系的输出样例
2. 补齐权威符号及关联，打通模型发布、模糊发现、精确 info 和片段校验
3. 对齐 LSP 展示并移除重复输出，用集成项目固定两仓版本验收

验收覆盖枚举声明与发布契约一致、普通稿件拒绝自定义枚举、合法成员可直接引用，以及声明隐藏 wire 后的筛选、分组、排序和原始字段查找。用可选关系验证成员自身可空性和查询结果可空性的区别。完整 DARI 示例由现有前端检查，验收过程无需执行查询。用实际任务比较发现到首份合法计划所需的知识调用。
